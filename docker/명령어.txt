컨테이너 실행
컨테이너는 기본적으로 로컬을 못 본다.
-v 는 그 벽에 구멍을 하나 뚫어서 로컬 폴더 하나만 보이게 한다.
docker run -d --name config-service -p 8888:8888 \
  -v /Users/kdw/Desktop/lect/msa/config-repo:/config-repo:ro \
  -e CONFIG_REPO_PATH=file:/config-repo \
  config-service:latest

*** docker compose ***
기동 (data -> service -> front)

-f (= file) - 어떤 컴포즈 파일을 쓸지 지정
-d (= detach) - 백그라운드 실행
1) 데이터 (mas-network 생성 + MySQL)
docker compose -f docker-compose.data.yml up -d

2) 서비스 (config -> auth/board/edge)
docker compose -f docker-compose.service.yml up -d --build

3) 프론트 (web)
docker compose -f docker-compose.front.yml up -d --build

--build 는 소스가 바뀌었을 때 이미지를 다시 만든다.
코드 수정 후 붙여야 반영된다.

종료 (역순 - front -> service -> data)
docker compose -f docker-compose.data.yml down
docker compose -f docker-compose.service.yml down
docker compose -f docker-compose.front.yml down

완전 초기화 (DB 데이터까지 삭제)
docker compose -f docker-compose.data.yml down -v
docker compose -f docker-compose.service.yml down -v
docker compose -f docker-compose.front.yml down -v

상태 확인
docker ps # 전체 컨테이너
docker compose -f docker-compose.service.yml ps # 해당 파일만
docker logs -f auth-service # 로그 확인
docker compose -f docker-compose.service.yml log -f # 해당 파일 전체 로그

개별 재시작
docker compose -f docker-compose.service.yml restart auth-service
# 코드 수정이 있었을 시
docker compose -f docker-compose.service.yml up -d --build auth-service
